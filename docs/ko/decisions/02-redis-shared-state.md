# Redis에 짧게 유지되는 공유 상태를 모음

## 상황

공통 API가 두 인스턴스로 동작했고, 발송과 토큰 갱신에 여러 프로세스가 함께 봐야 하는 상태가 있었다.

## 판단

다음 상태를 Redis에서 공유한다.

- FCM access token
- badge / 수신 대상 상태
- `messageId` 기준 발송 상태
- access token 갱신 조정 상태

이 선택은 메시지 broker를 새로 만든 것이 아니다. 짧은 유효시간과 빠른 조회가 필요한 운영 상태를 같은 저장소에서 공유한 것이다.

## 선택의 대가

- Redis 연결 상태가 실제 발송 가능 여부에 영향을 준다.
- 프로세스 기동 여부와 Redis 준비 상태를 따로 확인해야 한다.
- lock 만료와 작업 시간의 관계를 검증해야 한다.
- key, TTL, 실패 시 처리와 모니터링 기준이 필요하다.

## 공개 제한

실제 key, host, TTL, lock 시간, badge 계산 규칙과 수신 대상 식별값은 공개하지 않는다.
