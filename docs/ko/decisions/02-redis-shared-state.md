# Redis에 짧게 유지되는 공유 상태를 모음

## 상황

발송 경로에는 DB에서 조회하는 기준 데이터와, 여러 서버 프로세스가 짧게 공유해야 하는 운영 상태가 같이 있었다. 둘을 한 저장소의 역할처럼 설명하면 실제 구조와 달라진다.

## 판단

수신 대상과 단말 토큰은 DB Repository에서 조회하고, Redis에는 다음 상태만 둔다.

- FCM access token
- badge 상태
- `messageId` 기준 발송 상태
- access token 갱신 조정 상태

Redis를 메시지 broker나 Recipient DB처럼 쓰려는 선택이 아니었다. 짧은 유효시간과 빠른 공유가 필요한 상태에 사용했다.

## 선택의 대가

- Redis 연결 상태가 실제 발송 가능 여부에 영향을 준다.
- 프로세스 기동 여부와 Redis 준비 상태를 따로 확인해야 한다.
- lock 만료와 실제 갱신 시간의 관계를 검증해야 한다.
- key, TTL, 실패 시 처리와 모니터링 기준이 필요하다.

## 공개 제한

실제 key, host, TTL, lock 시간, badge 계산 규칙은 공개하지 않는다. 사용자·단말 식별값과 DB 구조도 공개하지 않는다.
