# `messageId`를 E2E 식별자로 사용

## 상황

하나의 발송 요청이 기존 업무 서비스, Java/데이터 전달, 연계 API, 공통 API, Redis 상태와 FCM 호출을 지난다. 서비스별 요청 ID만으로는 장애 때 같은 발송을 다시 이어 붙이기 어려웠다.

## 판단

업무 요청에서 정한 `messageId`를 끝까지 유지한다.

```text
Java/데이터 전달 로그
연계 API 로그
공통 API 로그
Redis 발송 상태
FCM 결과
          ↑ 같은 messageId
```

이 값은 로그 연결뿐 아니라 같은 요청의 반복 여부를 판단하는 기준으로도 사용한다.

## 선택의 대가

- 같은 `messageId`가 다른 payload에 재사용되는 경우를 막아야 한다.
- 상태 보관 기간이 끝난 뒤 들어온 오래된 재시도는 별도 정책이 필요하다.
- FCM과 단말까지 exactly-once를 보장하는 값으로 과장하지 않는다.

## 공개 제한

실제 ID 생성 규칙과 실제 값은 공개하지 않는다. 예제에서는 `messageId` 필드의 역할만 보여준다.
